# OpenCode 사용량 게시판

[English](README.md) | **한국어**

OpenCode V2 서버 플러그인이 **같은 프로세스에서** 제공하는 React + Bun 웹 UI입니다. 별도 DB, 수집기, 상시 실행 데몬 없이 공개 API만 읽습니다.

**OpenCode Mini 또는 전체 TUI에서 `/usage-dashboard`를 실행하면 대시보드가 열립니다.** `/` 자동완성에 표시되며 모델을 호출하지 않습니다. 플러그인을 불러올 때 자동으로 열지 않고, 사용자가 명령을 실행할 때만 브라우저를 엽니다.

- **개요:** 요약, 날짜별 Steps·토큰, 토큰 구성
- **모델:** 모델·variant별 토큰/비용 그래프와 표
- **도구:** 호출 상태 그래프와 실행시간 표
- **세션:** 제목 검색, 상·하위 세션, 요청별 컨텍스트

## GitHub에서 설치

첫 배포 워크플로 성공 후 빌드 결과가 포함된 `release` 브랜치를 `opencode.json`에 추가합니다:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["github:createOne999/oud#release"]
}
```

저장소가 비공개인 동안에는 대신 `git+ssh://git@github.com/createOne999/oud.git#release`를 사용하고, OpenCode 서버가 실행되는 PC에 GitHub SSH 접근을 미리 설정하세요. 공개 전환 후에는 위 GitHub 주소만으로 인증 없이 설치할 수 있습니다. 어느 방식도 npm 계정, `.npmrc`, `NODE_AUTH_TOKEN`이 필요하지 않습니다. `@opencode/*` 등 공개 런타임 의존성은 계속 npmjs에서 내려받습니다. [OpenCode의 Git 플러그인 지원](https://opencode.ai/v2/docs/plugins#manage)을 참고하세요.

OpenCode 2.2.0의 로컬 공유 서비스를 사용합니다. OpenCode에서 `/usage-dashboard`를 실행하세요. 실제 접속 주소도 로그에 표시됩니다. 기본 포트는 7331입니다. 여러 프로젝트나 전역 설정에서는 충돌을 피하도록 서로 다른 포트(또는 사용 가능한 포트를 선택하는 `0`)를 지정하세요:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    { "package": "github:createOne999/oud#release", "options": { "port": 7332 } }
  ]
}
```

Git으로 설치한 플러그인과 아래 로컬 소스 플러그인을 동시에 사용하지 마세요. 두 플러그인의 ID가 `local.usage-dashboard`로 같습니다. 전역 npm 설치나 사용자의 빌드/postinstall 단계는 필요하지 않습니다. release 브랜치에 빌드된 자산이 포함됩니다. 첫 배포 워크플로 성공 전에는 아래 소스 설정을 사용하세요.

## 소스에서 실행

OpenCode **2.2.0**, Bun **1.4.2** 환경을 기준으로 구현했습니다. 저장소 루트에서:

```powershell
bun run setup
opencode mini
# OpenCode 안에서: /usage-dashboard
```

저장소 루트의 `opencode.json`은 소스 사용을 위해 저장소 루트(`./`)를 플러그인으로 불러옵니다. 이 파일은 로컬 설정으로 유지되며 전역 설정은 변경하지 않습니다. 설정은 자동 반영되므로 이미 실행 중인 OpenCode에서는 서비스 재시작이 필요하지 않습니다. 반영되지 않으면 `/reload`를 사용하거나 프로젝트 루트에서 Mini를 다시 실행하세요.

브라우저를 열지 못한 경우에도 다음 명령으로 실제 접속 주소와 준비 상태를 터미널에서 확인할 수 있습니다:

```powershell
bun run status
```

설치한 패키지에서는 상태 스크립트를 직접 실행합니다(CLI bin 아님): `bun /path/to/node_modules/@createone999/oud/status.ts /path/to/project`.

이미 실행 중인 공유 서비스를 찾고 OpenCode의 인증된 플러그인 RPC로 조회하며, 서비스를 시작·재시작하지 않습니다. 먼저 프로젝트 디렉터리에서 Mini를 실행하세요. 준비 상태는 리스너·빌드 기준이며 데이터 조회 오류는 기존처럼 대시보드에서 안내합니다. 빌드 누락·포트 충돌·서비스 연결 실패는 다음 조치와 함께 안내합니다. 브라우저는 서버가 실행되는 PC에서 열리므로 헤드리스·원격·WSL 환경에서는 표시된 주소로 직접 접속하세요.

직접 접속할 때 기본 주소는 <http://127.0.0.1:7331/stats>입니다. `http://localhost:7331/stats`와 IPv6를 사용할 수 있는 환경의 `http://[::1]:7331/stats`도 지원합니다. 같은 기본 주소에 `/models`, `/tools`, `/sessions` 화면이 있습니다. 포트 옵션을 바꿨다면 7331로 추측하지 말고 `status`로 확인하세요. `port: 0`은 사용 가능한 포트를 선택합니다.

프런트엔드 수정 후 `build`를 다시 실행하면 다음 브라우저 새로고침부터 적용됩니다. 플러그인 서버 코드 수정 후에는 `/reload`로 플러그인을 다시 불러오세요. 플러그인 해제·재로딩 시 리스너를 닫습니다.

7331 포트가 이미 사용 중이면 플러그인 옵션만 변경합니다:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    { "package": "./", "options": { "port": 7332 } }
  ]
}
```

## 사용량

- 기간·프로젝트 필터: 기본값은 이번 달, 현재 프로젝트입니다. 선택한 종료일을 포함하며 브라우저의 시간대를 사용합니다.
- 상단 언어 선택기로 한국어·영어를 전환합니다. 기본값과 누락 번역 폴백은 한국어이며, `?lang=ko|en`을 화면 이동·새로고침·공유 링크에 유지합니다. 언어 변경 시 기존 필터·요청·커서·해시는 보존합니다.
- UI·차트·접근성 안내·날짜 표시만 번역하며 세션 제목·대화·도구 결과·모델명·경로 원문, 토큰 `K/M/B/T`, USD 비용과 집계 시간대는 유지합니다. 날짜 선택기 내부 문구는 브라우저 언어를 따릅니다. 번역은 `web/locales/ko.json`, `en.json`을 로컬 번들에 포함하며 외부 번역 서비스·자동 언어 감지·브라우저 저장소를 사용하지 않습니다.
- 세션·하위 세션·프롬프트·모델 Steps·활동일·최장 연속 활동일.
- 공급자·모델·variant별 입력·출력·추론·캐시 읽기/쓰기·전체 토큰·USD 비용. 토큰·비용·Steps·이름순 정렬.
- 도구별 호출·성공·실패·미완료 횟수 및 실행시간 P50(ms), 날짜별 Steps.
- 전체 토큰은 다섯 토큰 분류의 합입니다. 입력은 비캐시 입력, 출력은 추론을 제외한 가시 출력입니다.
- 토큰 표시는 1,000배 기준 `K`·`M`·`B`·`T`로 축약하고 소수점은 최대 두 자리입니다. 집계·정렬에는 원본 숫자를 사용하며 Steps·횟수·시간·비용 표시는 유지합니다.
- 비용은 공급자 보고액과 카탈로그 추정액이 섞일 수 있으며 API에 출처 구분이 없습니다. 단가 미등록으로 0이 될 수도 있어 실제 청구액 또는 무료 사용으로 단정하지 않습니다.
- 현재 API에서 compaction은 전체 합계에만 포함되므로 모델별 행 합계와 다를 수 있습니다. Title 사용량은 제외됩니다. Steps는 HTTP 요청 수가 아닙니다.
- 날짜별 Steps는 활동 기록이 있는 날짜만 표시합니다. **일별 토큰 불러오기**를 누르면 선택한 기간을 브라우저 시간대의 1일 단위로 나눠 입력·출력·추론·캐시 읽기/쓰기 그래프와 데이터 표를 표시합니다. 조회 기간은 기존 시작일·종료일로 선택합니다.
- 일별 토큰은 공개 `session.stats`를 하루당 한 번씩 순차 조회하며 도구 집계는 제외합니다. 조회 실패 시 일부 값을 0으로 채우거나 완전한 결과로 표시하지 않습니다. Steps가 없는 날의 압축 사용량도 포함하려고 모든 날짜를 조회합니다. 전체 세션·대화 본문 수집이나 추가 저장은 하지 않습니다. 조회 시점이 달라 실행 중인 요청의 사용량은 상단 합계와 차이 날 수 있습니다.
- 모델·도구 그래프는 앞 10개, 표는 전체 항목입니다. 모델 그래프는 표와 같은 정렬을 따릅니다.
- 기간·프로젝트는 URL에 유지됩니다. 세션 목록은 프로젝트·제목과 최근 수정 순서로 조회하며, 기간 필터는 세션 상세에서 불러온 요청에 적용됩니다. 세션 누적 토큰·비용은 기간 집계가 아닙니다.

## 요청 시점의 컨텍스트

1. **세션 / 요청**에서 세션을 선택합니다. 하위 세션은 상세의 `하위 세션` 또는 목록의 `하위 세션` 표시로 찾습니다.
2. 요청 그래프의 점이나 표의 요청 시각을 선택합니다. 키보드 사용자는 같은 요청 시각 링크를 사용할 수 있습니다.
3. 선택 시점으로 이동해 **요청 직전 저장 이력**과 **선택한 요청의 응답**을 따로 봅니다. URL의 `request`와 페이지 `cursor`를 함께 유지하므로 해당 링크를 다시 열거나 새로고침할 수 있습니다.
4. `이전 이력 100개 더 보기`로 앞부분을 읽습니다. 압축 요약, 저장된 지침 변경, 스킬, 사용자 메시지, 이전 응답과 도구 결과를 볼 수 있습니다. 바이너리 첨부는 이름·형식만 표시하고 외부 파일/URL은 자동으로 열지 않습니다.

### 정확성·조회 범위

- **저장 이력 기반 재구성이지 실제 전송 원문이 아닙니다.** 현재 `session.context()`를 과거 요청에 재사용하지 않습니다. 당시 시스템 지침 전체·도구 정의·플러그인 변환·공급자 최종 입력은 복원하지 않습니다.
- 저장된 메시지 순서상 선택한 Step 이전 항목만 사용하고, 발송 뒤 기록된 입력도 제외합니다. 응답은 별도 영역에 두고, 그 이후 메시지는 입력 이력에 섞지 않습니다. 요청 전에 완료된 것으로 확인되지 않은 이전 응답·도구·셸 결과는 제외합니다. 원본은 현재 투영본이므로 이 검증만으로 당시 상태의 완전 복원을 보장하지는 않습니다.
- 완료된 압축을 경계로 원기록을 구분합니다. 유지 텍스트 또는 `keepID` 참조를 표시하며, 아직 불러오지 않았거나 누락된 유지 기록은 불완전함을 알립니다. 공급자 압축 창은 같은 공급자·모델일 때만 경계로 사용하고, 원시 재생 데이터는 노출하지 않습니다.
- 세션은 20개, 메시지는 100개씩 공개 API의 커서로 읽습니다. 요청 그래프는 **현재 불러온 메시지 페이지에서 기간에 맞는 Steps만** 표시하며 전체 세션 추이라고 주장하지 않습니다. 요청이 없는 페이지에서도 다음 페이지로 이동할 수 있습니다.
- 요청 그래프의 입력 컨텍스트 토큰은 `input + cache.read + cache.write`, 생성 토큰은 `output + reasoning`입니다. 입력 토큰은 모델 최대 컨텍스트 크기나 점유율이 아닙니다. 없는 측정값은 `미집계`로 남기며 0과 구분합니다.
- 요청 단위는 기록된 모델 Step입니다. 모든 HTTP 요청·재시도의 독립적인 목록은 아닙니다. `session.log()`는 기본 이벤트 보관이 꺼져 있으면 과거 이벤트 없이 `log.synced`만 반환할 수 있어 이 기능의 필수 데이터로 사용하지 않습니다.
- 이력이 변경되어 요청과 커서가 맞지 않으면 재선택을 안내합니다. 과거 위치를 찾으려고 전체 세션을 자동 스캔하지 않습니다.

## 연결·보안·제약

- 공식 `Service.discover()`로 **이미 실행 중인 로컬 공유 서비스**를 찾습니다. 서비스를 시작·중지·교체하지 않습니다. `--standalone` 및 원격 `--server` 연결은 이 버전의 대상이 아닙니다.
- 브라우저는 Bun의 제한된 조회 API에만 접근합니다. OpenCode 인증 헤더·비밀번호는 서버 메모리에만 있고 브라우저에 전달하거나 파일에 저장하지 않습니다.
- 루프백(`127.0.0.1`, 사용 가능한 환경의 `::1`)에만 바인딩합니다. `localhost`를 포함한 실제 포트의 루프백 주소만 허용하고, Origin이 있으면 해당 요청 주소와 정확히 일치해야 합니다. Host/Origin/Fetch Metadata 및 커스텀 요청 헤더를 검증하며 CORS와 쓰기 요청은 계속 차단합니다. 사설 IP/LAN 접속, 로컬 OS 사용자 간 격리, 외부 공개 서비스용 로그인 기능은 제공하지 않습니다.
- 슬래시 명령과 상태 RPC는 OpenCode의 기존 명령·인증 경로를 사용합니다. 별도 대시보드 리스너가 `opencode serve` 인증을 상속하는 것은 **아니며**, 로컬 전용을 유지합니다. 비밀번호를 URL·브라우저 설정에 복사하거나 CORS 허용 범위를 늘리지 않습니다.
- React/CSS/차트는 로컬 빌드 결과로 제공하며 CDN·외부 폰트·텔레메트리를 사용하지 않습니다. 요청을 선택했을 때 필요한 저장 대화·도구 결과만 화면용으로 조회합니다. 목록에는 본문을 전달하지 않으며, 조회 내용을 로그·파일·브라우저 DB에 추가 저장하지 않습니다.
- 사용량 API는 experimental입니다. DB를 직접 읽거나 OpenCode 내부 구현을 import하지 않습니다.
- 한 프로젝트에서 한 인스턴스를 사용하는 최소 구성입니다. 다른 프로젝트에서도 동시에 플러그인을 활성화하려면 포트를 다르게 지정하세요.
- 자동 폴링 대신 조회/새로고침 시에만 API를 호출합니다. 데이터가 없거나 연결에 실패하면 화면에서 안내합니다.
- 제거하려면 플러그인을 추가한 OpenCode 설정에서 해당 항목을 지우세요. 이 플러그인이 저장한 사용량 데이터는 없습니다.
- `reference/opencode/`는 읽기 분석용이며 OpenCode DB·스키마·설정·저장 방식은 변경하지 않습니다. `ctx.storage`를 포함한 추가 저장·캡처도 하지 않습니다.

## 디자인

- Tailwind CSS v4와 shadcn/ui(Radix 기반), Lucide React를 유지하고 상단 내비게이션으로 페이지를 나눕니다. React Router나 상태관리 라이브러리는 추가하지 않고 일반 링크와 URL 필터를 사용합니다.
- `web/components/ui/`는 shadcn/ui 소스입니다. `components.json`으로 필요한 컴포넌트만 추가하며, 날짜와 프로젝트 선택은 네이티브 입력 동작을 유지합니다.
- Recharts 3.10.1로 막대·선 그래프, 툴팁, 기본 방향키 탐색을 재사용합니다. `react-is`는 설치된 React와 같은 19.3.1로 맞춥니다. 테이블은 기존 shadcn Table과 단순 정렬을 유지하며 TanStack Table은 추가하지 않습니다.
- `build.ts`가 Bun의 Tailwind 플러그인으로 HTML·JS·CSS를 빌드합니다. 자산은 루트 절대 경로로 제공해 세션 상세 주소에서 새로고침해도 로드됩니다. CSS는 별도 로컬 파일로 제공하여 기존 CSP를 유지합니다.
- 그래프 애니메이션은 끄고 짧은 CSS 전환만 사용하며 `prefers-reduced-motion`을 존중합니다. Motion·React Aria·reactbits는 추가하지 않습니다. 집계 그래프에는 접을 수 있는 데이터 표, 요청 그래프에는 동일 시점의 요청 링크를 제공합니다.

## 배포

CI는 pull request와 `main` 푸시에서 고정 Bun lockfile을 사용해 typecheck → build → test 순서로 실행합니다. 배포는 일반 GitHub Release를 게시할 때만 실행되며(draft와 prerelease 제외), 태그는 `v<package.json 버전>`과 정확히 일치해야 합니다. 버전은 자동으로 올리지 않습니다. 워크플로는 Bun 1.4.2를 사용합니다.

배포 워크플로를 `main`에 푸시한 뒤 해당 소스 커밋에서 `v<package.json 버전>`(현재 `v0.1.0`) 태그로 일반 GitHub Release를 게시합니다. 워크플로가 검사를 실행하고, `package.json`의 파일 목록으로 런타임 파일과 빌드된 `dist/`를 묶어 자동 `GITHUB_TOKEN`과 `contents: write` 권한으로 `release` 브랜치를 생성하거나 갱신합니다. npm 게시나 별도 PAT는 사용하지 않습니다. 저장소 규칙에서 워크플로의 `release` 브랜치 푸시를 허용해야 합니다.

`main`과 소스 태그에는 빌드 결과를 커밋하지 않고, `release`에만 `dist/`를 포함합니다. 설치 주소에 `#v0.1.0` 같은 소스 태그를 사용하지 마세요. 특정 배포를 고정하려면 `#release` 대신 release 브랜치의 전체 커밋 해시를 지정하세요. 배포 커밋은 이전 배포 이력을 이어가며 강제 푸시하지 않습니다.

이후 배포는 `package.json` 버전을 올려 커밋·푸시한 뒤 해당 소스 커밋에서 일치하는 `v<버전>` 태그의 일반 GitHub Release를 게시합니다. 공개 전환 전 다른 PC의 별도 빈 프로젝트에서 로컬 `./` 플러그인 없이 비공개 SSH 설치를 확인하세요. 저장소를 공개하면 위 GitHub 플러그인 항목만으로 설치할 수 있습니다.
